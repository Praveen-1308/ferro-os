⚖️ Why We Engineered the 50-50 Normalization (Standardization Rationale)

Earlier versions exhibited extreme polarization: an aggressive 250 µs preemption slice burned 6–8% of the single vCPU on hyperactive context switching and starved background disk I/O, while unthrottled connection acceptance caused servers to crash into a hard brick wall at 500 VUs. The 50-50 Normalized State standardizes three core architectural trade-offs:

1. Balanced CPU Slices (2,000–5,000 µs) Gives background SQLite WAL flushes sufficient CPU quantum to release table locks without starving incoming web requests, avoiding tail latency blowouts.
2. Bounded In-Flight Concurrency (32 Max) Limits concurrent workers to the single-core sweet spot; excess traffic receives instantaneous userspace HTTP 429 (< 5µs) with Retry-After headers, preventing socket queue exhaustion.
3. Lookaside & Arena Memory Pooling Caps SQLite lookaside to 256 KB per connection with MIMALLOC_PURGE_DELAY=2, keeping memory flat at ~20 MB and eliminating memory fragmentation during bursts.
